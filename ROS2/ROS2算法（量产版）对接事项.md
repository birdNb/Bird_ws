# ROS2算法（量产版）对接事项

## 文档介绍

本文档旨在梳理 ROS2 算法手柄操作、操作逻辑、上层控制接口和方法等关键信息。如果内容有问题请及时反馈。

章节内容由**原算法 ROS1**、**新算法 ROS2**、**ROS2 修改建议**、**非手柄操作方法（上层控制接口）** 四个主要章节组成。

## 一、设计原则

对于量产版算法，在设计手柄操作机器人时需尽可能遵守如下原则：

1.  尽可能保留 ROS1 用户操作使用习惯。
    
2.  相同动作的手柄触发方式或者其他调用方式尽可能保持一致。
    
3.  为适配新框架必须要修改时，一旦增删或者修改按键、操作逻辑需要提供：修改说明、原键位表、新键位表。
    
4.  需要维护算法的版本号，并制定开发测试计划。文件内容需按照算法版本实时更新。
    

## 二、机器人底层状态（底层FSM状态）

机器人底层状态又称为底层FSM状态，受到服务 `/hightorque_controller/change_fsm_state` 控制。触发方式有多种：手柄触发、非手柄触发、硬件状态触发（例如故障）。

### 1. 原状态（ROS1）

| 状态名 | 含义 |
| --- | --- |
| NONE | 无控制器运行，或候选/未实现执行状态 |
| INITIAL | 初始化模式 |
| DEFAULT | 默认行为树控制模式，主要运动和策略执行模式 |
| DEVELOP | 开发模式 |
| PROTECT | 保护模式 |
| ERROR | 错误模式 |
| RESETZERO | 电机零位置置模式 |
| REMOTE | （含义待补充） |
| TEACH | 示教模式 |
| CUSTOM | （含义待补充） |

**状态切换逻辑说明：**

*   进入 DEFAULT 方式：机器人无故障开机自动进入，或从任意状态按手柄 `[HOME]` 键
    
*   进入 PROTECT 方式：硬件故障触发或 `(LT + RT + B) × 1`
    
*   进入 INITIAL 方式：`(LT + RT + B) × 2`
    
*   进入 ERROR 方式：机器人开机时存在故障（例如电机未启动）
    
*   切换其他底层模式（在 INITIAL 状态下）：  按住 `LT+RT`，再按十字键左或十字键右，可在以下状态间循环遍历（左右可正向/反向切换）：   `INITIAL → DEFAULT → CUSTOM → REMOTE → RESETZERO → RESETZERO → TEACH → DEVELOP → INITIAL`**注意**：除 INITIAL 之外，其他状态需要按 `LT+RT+A` 确认选中后方可生效。
    

### 2. 修改后（ROS2）

| 业务名称 | 含义 |
| --- | --- |
| INITIAL | 初始化模式 |
| ERROR | 错误模式 |
| DEFAULT 候选 | DEFAULT 候选状态 |
| DEFAULT | 默认行为树控制模式，主要运动和策略执行模式 |
| PROTECT | 保护模式 |
| RESETZERO 候选 | RESETZERO 候选状态 |
| RESETZERO | 电机零位重置模式 |
| RESET DONE | 电机零位重置成功，约 3 秒后自动回到 INITIAL |
| RESET FAIL | 电机零位重置失败，约 3 秒后自动回到 INITIAL |

**状态切换逻辑说明：**

*   进入 DEFAULT 方式：机器人无故障开机自动进入，或从任意状态按手柄 `[HOME]` 键
    
*   进入 PROTECT 方式：硬件故障触发或 `(LT + RT + B) × 1`
    
*   进入 INITIAL 方式：`(LT + RT + B) × 2`
    
*   进入 ERROR 方式：机器人开机时存在故障（例如电机未启动）
    
*   切换其他底层模式（在 INITIAL 状态下）：  按住 `LT+RT`，再按十字键左或十字键右，可在以下状态间循环遍历（左右可正向/反向切换）：   `INITIAL → DEFAULT 候选 → RESETZERO 候选`**注意**：候选状态需要按 `LT+RT+A` 确认选中后方可生效。
    

> **说明**：ROS2 中底层 FSM 已与手柄解绑，上表仅为手柄操作方式的参考映射。实际开发中推荐使用非手柄方式（服务接口）进行底层状态控制，具体请参考本章第 4 节。

## 三、机器人上层状态切换

### 1. 原状态（ROS1）

机器人上层状态对应于行为树（MainTree）的各个子节点，具体如下：

| 状态名（小写） | 功能说明 |
| --- | --- |
| init | 初始化，申请电机控制权 |
| standing | 站立状态，执行站立策略 |
| running | 运行状态，执行运动策略 |
| standby | 待机状态，保持姿态 |
| siting | 坐下状态，执行坐下动作 |
| policy switch | 策略切换，热切换策略 |
| policy recovery | 策略恢复，跌倒恢复 |

**状态切换逻辑说明：**

*   进入 `init` 状态：机器人成功开机之后自动进入 `init` 状态
    
*   进入 `standing` 状态：机器人在 `init` 状态时，按 `LT+RT+START` 后进入 `standing` 状态
    
*   进入 `standby` 状态：机器人 `standing` 完成后自动进入 `standby`。或者机器人在 `running` 状态时按 `LT+RT+LB` 进入 `standby`
    
*   进入 `running` 状态：当机器人处在 `standby` 状态时，按 `LT+RT+LB` 进入 `running` 状态
    
*   进入 `siting` 状态：机器人在 `standby` 或 `running` 状态时，按 `LT+RT+RB` 进入 `siting` 状态
    
*   `policy switch`：`standby` 状态下，`LT+RT+十字键左键或右键` 切换不同的策略
    
*   `policy recovery`：机器人跌倒时，自动触发跌倒恢复
    

### 2. 修改后（ROS2）

| 状态名（小写） | 功能说明 |
| --- | --- |
| `init` | 初始化，申请电机控制权 |
| `standing` | 站立状态，执行站立过程 |
| `running` | 运行状态，执行运动策略 |
| `standby` | 待机状态，保持姿态 |
| `siting` | 坐下状态，执行坐下动作 |

> **说明**：ROS2 中已移除 `policy switch` 和 `policy recovery` 状态。策略切换由 PKL 动作源数据替代，具体策略调用方式见下文。

**状态切换逻辑说明：**

*   进入 `init` 状态：机器人成功开机后自动进入 `init`
    
*   进入 `standing` 状态：机器人在 `init` 状态时，按 `LT+RT+START` 进入 `standing`，执行站立过程，完成后自动进入 `standby`
    
*   进入 `standby` 状态：机器人 `standing` 完成后自动进入 `standby`；或机器人在 `running` 状态时按 `LT+RT+LB` 进入 `standby`（停止策略、回正姿态、释放控制权）
    
*   进入 `running` 状态：当机器人处在 `standby` 状态时，按 `LT+RT+LB` 进入 `running`
    
*   进入 `siting` 状态：机器人在 `standby` 状态时，按 `LT+RT+RB` 进入 `siting`，执行坐下动作，完成后进入内部 `init`（`running` 状态不能直接进入 `siting`）
    

> **注意**：

## 四、机器人内置步态策略切换

### 1. 原策略（ROS1）

机器人上层状态对应于行为树（MainTree）的各个子节点，具体如下：

| 状态名（小写） | 功能说明 |
| --- | --- |
| amp | 全身控制策略 |
| lr | 下半身控制策略 |
| 其他几种步态 | 全身控制策略 |

**策略切换逻辑说明：**

*   进入 `init` 状态：机器人成功开机之后自动进入 `init` 状态
    
*   进入 `standing` 状态：机器人在 `init` 状态时，按 `LT+RT+START` 后进入 `standing` 状态
    
*   进入 `standby` 状态：机器人 `standing` 完成后自动进入 `standby`。或者机器人在 `running` 状态时按 `LT+RT+LB` 进入 `standby`
    
*   在 `standby`状态：长按 `LT+RT`，利用十字键切换不同的步态策略。
    

### 2. 修改后（ROS2）

| 策略名称（`policy_name`） | 功能说明 |
| --- | --- |
| `bfm` | BFM 动作策略，当前默认策略 |
| `amp` | AMP 行走策略 |
| `amp_lower` | AMP 下半身行走策略，同时用作 waypoint 支持策略 |

> **说明**：策略名称区分大小写，必须使用小写形式（`bfm`、`amp`、`amp_lower`）。

**策略切换逻辑说明：**

*   切换前提：底层 FSM 已进入 `EXEC_DEFAULT`，且 `current_mode` 为 `default_bt`，`current_state` 为 `STANDBY` 或 `RUNNING`
    
*   完成以上前提之后：
    
    *   进入 `bfm`：`LT + Y`
        
    *   进入 `amp`：`LT + 左摇杆按下`
        
    *   进入 `amp_lower`：`LT + 右摇杆按下`
        

> **注意**：切换策略时，下一个策略稳定需要一定的时间，一般为 3~5 秒。

### 3. 步态策略修改建议

1.  由于步态切换策略比较重要，如果在运动状态时进行了策略切换容易使机器人不稳定，键位配置应按照复杂组合键设计。建议修改为：
    
    *   进入 `bfm`：`LT + RT + X`或者`LT + RB + 左摇杆按下`
        
    *   进入 `amp`：`LT + RT + 左摇杆按下`
        
    *   进入 `amp_lower`：`LT + RT + 右摇杆按下`
        
        **设计原因：**
        
    *   `LT` 在 ROS1 的习惯里是步态的加速键，`LT` 持续按下加上方向键，机器人可以加速运动。然而，这个操作容易造成摇杆误按下。因此策略切换需要更复杂的三按键组合。
        
    *   `LT+RT+A`、`LT+RT+B`、`LT+RT+Y` 三类按键组合在 ROS1 中已被舞蹈和紧急保护占用。为保留用户习惯，只剩下 `LT+RT+X` 可使机器人进入 `bfm`。
        

> **未来扩展建议**：若有更多步态策略，可加入 `RB`、`LB` 完成组合键配置。最少以三按键触发。三按键最好为左右手同时配合，比如左手按两个右手按一个（LT+RB+左摇杆按下），既保证提高触发难度，又在操作上比较顺手。

## 五、基本运动

### 1. ROS1 控制机器人基本运动

| 运动 | 操作方式 |
| --- | --- |
| 前进 | 左摇杆前推 |
| 后退 | 左摇杆后推 |
| 左移 | 左摇杆左推 |
| 右移 | 左摇杆右推 |

| 右前 | 左摇杆向右前方推 |
| 左后 | 左摇杆向左后方推 |
| 右后 | 左摇杆向右后方推 |
| 原地左转 | 右摇杆左推 |
| 原地右转 | 右摇杆右推 |
| 前进时右转 | 左摇杆前推 + 右摇杆右推 |
| 前进时左转 | 左摇杆前推 + 右摇杆左推 |
| 后退时右转 | 左摇杆后推 + 右摇杆右推 |
| 后退时左转 | 左摇杆后推 + 右摇杆左推 |
| 加速 | LT长按+以上按键 |

> **说明：**

*   斜向运动（左前、右前、左后、右后）通过左摇杆对角线方向实现。
    
*   组合转向在直行基础上叠加右摇杆的转向指令，实现前进/后退同时转向。

2.  新增动作需要按照以下原则进行开发和键位配置：
    
    *   简单动作单一键位。
        
    *   复杂、长时序、高难度动作采用组合键。
        
    *   动作名需要有中文和英文，名称唯一，键位不重复的。
        
    *   同一个动作优化迭代时命名采用名称+数字的方式以区分不同版本的动作，数字越大动作越好。
        
    *   按键不应该与其他功能键（例如状态切换冲突）
        
3.  动作或者音频触发不应该与手柄话题绑定，需要单独的话题控制。
    
4.  动作和音频应该解绑，动作、音频可以分别单独触发，动作和音频可以通过一个按键同时触发。通过配置文件可以修改这个规则。
    
5.  动作库和音频库路径尽可能与 ROS1 保持一致，如果修改需要及时通知。
    

### 4. 非手柄方式控制机器人动作或音频播放

请告知如何通过其他方式控制机器人动作和音频播放，例如：

*   非手柄话题或服务
