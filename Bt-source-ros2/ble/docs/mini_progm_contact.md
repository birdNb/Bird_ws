# 蓝牙通讯协议与指令总表

本文以当前小程序代码为准，列出小程序会实际写入机器人 BLE 的全部指令及其用途。

## 1. 通讯约定

小程序使用 BLE GATT 通讯：下行（小程序 → 机器人）写入 FFE1；上行（机器人 → 小程序）由 FFE2 Notify 推送。

| 角色 | UUID | 用途 |
| --- | --- | --- |
| 主服务 | `0000FFE0-0000-1000-8000-00805F9B34FB` | BLE 服务 |
| 写入特征 | `0000FFE1-0000-1000-8000-00805F9B34FB` | 小程序下发 |
| 通知特征 | `0000FFE2-0000-1000-8000-00805F9B34FB` | 机器人状态上报 |

- 正常文本指令均为 UTF-8 纯文本，不包含换行、长度前缀或日志前缀。
- 日志中的 `TX ` 只表示“本条为发送记录”，`RX ` 只表示“本条为接收记录”；二者绝不写入 FFE1，也不是固件协议的一部分。
- 日志显示规则：`TX` 为蓝色，`RX` 为红色，灰色文字为本地备注，不代表任何 BLE 下发。
- 设备广播名匹配 `Humanoid-` 前缀，兼容测试设备 `Bird_BLE_Test`。

## 2. 建链与恢复

连接完成后，应尽快按以下顺序完成：

1. 向 FFE1 写入 `M_default`。
2. 启用 FFE2 Notify。

完整重连会重新执行上述握手；仅刷新通知订阅时无需重复写入 `M_default`。小程序对关键指令使用串行可靠写入；断链或写失败时会自动尝试重建连接并重新握手。

## 3. 下行文本指令（FFE1）

### 3.1 运动摇杆

格式：`X:{x},Y:{y},Z:{z}`。

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `X` | `-1.00` ～ `1.00`；疾跑时 `-1.80` ～ `1.80` | 前后平移，前为负、后为正 |
| `Y` | `-1.00` ～ `1.00`；疾跑时 `-1.80` ～ `1.80` | 左右平移，左为正、右为负 |
| `Z` | `-1.50` ～ `1.50` | 自转，左转为负、右转为正 |

示例：

```text
X:0.35,Y:-0.12,Z:0.00
X:0.00,Y:0.00,Z:0.00
```

摇杆激活时按 25 Hz 发送；松手发送全零包。摇杆实时包优先使用无响应写入，并与普通指令串行化。

### 3.2 建链与安全控制

| 指令 | 用途 | 典型触发 |
| --- | --- | --- |
| `M_default` | 建链默认握手 | 首次连接或完整重连后的握手；**不用于模式菜单切换** |
| `M_protect` | 保护/急停模式 | 急停、离开遥控页、切后台 |

模式切换一律使用下方“模拟手柄组合键”，不再向 FFE1 直接下发 `M_init`、`M_resetzero`、`M_tech` 或 `M_default` 来切换模式。

### 3.3 连接心跳

当小程序连续 3 秒没有向 FFE1 写入任何内容时，会发送一条纯文本心跳：

| 指令 | 周期 | 用途 |
| --- | --- | --- |
| `1` | 空闲满 3 秒后发送；后续每 3 秒一次 | 保持并确认 BLE 写入链路可用 |

`1` 是实际发送给机器人的协议内容，因此日志会显示为蓝色 `TX 1`；`TX` 仅是日志前缀，不属于下发数据。任何其他成功下行写入都会重新计时，使本次心跳延后。

从机侧超时规则：若机器人连续 **7 秒**未接收到任何下行指令或心跳 `1`，应主动断开 BLE 连接。小程序以最长 3 秒的空闲心跳周期维持链路，为该超时保留恢复余量。

### 3.4 电机、步态、语音与识别开关

| 指令 | 用途 |
| --- | --- |
| `MP ON` | 开启电机电源 |
| `MP OFF` | 关闭电机电源 |
| `GAIT ON` | 开启行走/拖拽所需步态 |
| `GAIT OFF` | 关闭步态、回站立状态 |
| `LT ON` | 开启疾跑范围 |
| `LT OFF` | 关闭疾跑范围 |
| `SOUND ON` | 开启语音提醒/回传 |
| `SOUND OFF` | 关闭语音提醒/回传 |
| `PULL ON` | 开启拖拽模式 |
| `PULL OFF` | 关闭拖拽模式 |
| `locate_face ON` | 开启人脸跟踪 |
| `locate_face OFF` | 关闭人脸跟踪 |

部分固件在执行 `MP ON` 时会重置蓝牙模块并短暂断链；小程序会自动重连、重新握手后恢复通道。此阶段不应持续操作摇杆。

### 3.5 音量、脖子、Wi-Fi 与重命名

| 格式/指令 | 参数 | 用途 |
| --- | --- | --- |
| `V {0..150}` | 整数 | 设置音量，例如 `V 80` |
| `neck0` | 无 | 脖子回中 |
| `P1Y0` | 无 | 脖子上仰一个单位（约 10°） |
| `P-1Y0` | 无 | 脖子下俯一个单位（约 10°） |
| `P0Y-1` | 无 | 脖子左转一个单位 |
| `P0Y1` | 无 | 脖子右转一个单位 |
| `WIFI {ssid} {password}` | SSID、密码 | 配置并连接 Wi-Fi；密码为空时末尾空格会被省略 |
| `rename+{name}` | 仅英文和数字 | 修改设备广播名 |

示例：

```text
V 80
WIFI OfficeNet password123
rename+Robot01
```

### 3.6 模拟手柄组合键与动作

组合键以原样纯文本写入 FFE1，按键名大小写必须与下表一致。

| 指令 | 用途 |
| --- | --- |
| `LT+RT+start` | 站立 |
| `LT+RT+RB` | 蹲下 |
| `RT+A` | 挥双手；mini_Pi 为扭腰 |
| `RT+X` | 单手挥；mini_Pi 为摇摆 |
| `LT+RT+LB` | 切换步态 |
| `LT+RT+B` | 卸力；在部分模式流程中用于进入/退出初始化状态 |
| `center` | 任意状态回默认模式 |
| `start+B` | 默认模式进入初始化候选状态 |
| `LT+RT+dpu` | Pi_Plus：选择调零候选状态 |
| `LT+RT+dpr` | Pi_Plus：选择默认候选状态；mini_Pi：下一模式 |
| `LT+RT+dpl` | 选择示教候选状态 |
| `LT+RT+A` | 确认当前候选模式/确认调零 |
| `A` | mini_Pi：增加步频 |
| `X` | mini_Pi：增大步幅 |
| `RT+Y` | mini_Pi：压腿 |
| `RT+B` | mini_Pi：一字马 |
| `Y` | mini_Pi：降低步频 |
| `B` | mini_Pi：减小步幅；Pi_Plus 默认动作“挠头” |

Pi_Plus 的模式切换会根据当前 FSM 自动选择并串行发送上述组合键：

| 目标模式 | 组合键路径示例 |
| --- | --- |
| 默认 | `center` |
| 初始化 | `start+B`；若当前为保护模式则使用 `LT+RT+B` |
| 保护 | 默认模式下发送 `LT+RT+B`；其他状态先 `center` 再发送 `LT+RT+B` |
| 示教 | `start+B` → `LT+RT+dpl` |
| 调零 | `start+B` → `LT+RT+dpu`，再通过 `LT+RT+A` 确认 |

不同起始 FSM 的路径可略有不同，但全程仅发送模拟手柄组合键。

#### mini_Pi 模式切换

mini_Pi 的模式切换说明置于 Pi_Plus 规则之后。模式菜单只模拟手柄按键，不发送 `M_*` 文本模式指令。

| 菜单操作/目标 | 模拟手柄指令 |
| --- | --- |
| 初始化 | `LT+RT+B`；已经处于初始化状态时不发送 |
| 下一模式 | `LT+RT+dpr` |
| 进入当前候选模式 | `LT+RT+A` |
| 切换默认模式 | 如未处于初始化：`LT+RT+B` → `LT+RT+dpr` → `LT+RT+A`；已处于初始化则省略第一步 |
| 切换调零模式 | 如未处于初始化先 `LT+RT+B`，再发送 `LT+RT+dpr` 四次，最后发送 `LT+RT+A` |

### 3.8 自定义指令

当前自定义动作输入只允许英文字母、`+` 与 `_`；会按输入内容分为以下两类：

| 输入形式 | 实际下发内容 |
| --- | --- |
| 含 `+` 的组合键，例如 `RT+Y` | 原样作为组合键文本发送 |
| 其他非空文本，例如 `wave_hello` | 原样作为文本发送 |

## 4. 下行二进制帧

除文本协议外，小程序仍保留内部动作码的二进制兼容路径。

| 类型 | 二进制格式 | 说明 |
| --- | --- | --- |
| 动作码 | `[0x02, 0x01, actionCode]` | 内部兼容动作码接口；当前默认动作库走文本组合键 |

已保留但当前主页面不作为常规下发路径的兼容二进制帧：

| 类型 | 格式 |
| --- | --- |
| 急停 | `[0x03, 0x00]` |
| 脖子 | `[0x04, 0x01, direction]` |
| 模式 | `[0x05, 0x01, modeCode]` |
| 语音开关 | `[0x07, 0x01, 0/1]` |
| 手势开关 | `[0x08, 0x01, 0/1]` |

## 5. 上行通知（FFE2 Notify）

通知可为单行或多行文本；多行以 `\r` 或 `\n` 分隔。当前小程序识别以下内容：

| 格式 | 用途 | 示例 |
| --- | --- | --- |
| `IP:{IPv4}` | 机器人局域网 IP | `IP:192.168.99.88` |
| `WIFI OK` | Wi-Fi 已连接 | `WIFI OK` |
| `WiFi disconnected` | Wi-Fi 已断开 | `WiFi disconnected` |
| `pwr:{0..100}` | 电池百分比 | `pwr:76` |
| `mode:{command}` | 模式变化通知（推荐） | `mode:M_default` |
| `fsm:{n}` | 运行状态机编号（兼容旧版） | `fsm:5` |
| `ACK:{command}` | 指令执行确认 | `ACK:MP ON` |
| JSON 状态包 | 兼容旧固件 | 含 `battery`、`temperature`、`jointTemps`、`firmware` 等字段 |

### 5.1 各模式状态返回格式

当前推荐使用 `mode:{command}` 作为模式状态回传格式（比 `fsm:{n}` 更直观）。

| 模式语义 | 回传格式（推荐） |
| --- | --- |
| 默认模式 | `mode:M_default` |
| 初始化模式 | `mode:M_init` |
| 保护模式 | `mode:M_protect` |
| 调零模式 | `mode:M_resetzero` |
| 示教模式 | `mode:M_tech` |

说明：

- `mode:*` 在订阅后会按当前状态推送一次，后续模式变化再推送一次。
- `fsm:{n}` 仍可保留用于兼容旧版解析，不建议作为主显示字段。

## 6. 发送与稳定性要求

- 摇杆包按 25 Hz 发送，普通指令与摇杆写入共用串行通道，避免并发写导致断链。
- 连续 3 秒无下行写入时发送文本心跳 `1`；任何成功写入都会重置心跳空闲计时。
- 模式切换为关键离散指令，按顺序发送；Pi_Plus 每步间隔约 400 ms，mini_Pi 每步间隔约 500 ms。
- 普通关键指令优先使用有响应写入；需要时可回退无响应写入。
- 写失败或明确断链时，小程序自动重连、重新订阅 FFE2 并重新握手；不将蓝牙 API 查询失败直接判定为断链。
- 切后台时发送 `M_protect` 进入安全态，但不会因页面切换主动关闭 BLE 连接。
